1. Timestamps + clickable footage
Each track now records first_seen/last_seen. On a crossing/breach the pipeline fires the instant live alert and rolls an evidence clip via the new ClipRecorder: it keeps a 3s pre-event buffer, writes frames throttled to a target fps (so playback is real-time paced), and stops once the object has been gone 2s or 20s max. When the incident ends, a record with ts_start → ts_end, duration, snapshot, and clip URL is persisted to logs/events.jsonl via EventStore.
The dashboard gains an Incident History panel — each row shows the time window + duration and opens the footage in a modal player (GET /api/events serves history; /clips serves the videos). Clips are written as browser-playable H.264 mp4 via imageio/ffmpeg, with an OpenCV mp4v fallback, and if neither codec is available the incident still records with its snapshot and timestamps (graceful degradation).
One caveat worth knowing for the demo: clip timing is accurate for live RTSP/webcam sources but slightly time-compressed for fast-read file sources — documented in the md file.
2. Load-aware, intelligent priority
The scheduler no longer enforces a fixed cap. A background sampler reads GPU utilisation (via nvidia-ml-py) — or CPU% (psutil) when there's no GPU — and adjusts a live effective_slots value with a proportional controller + hysteresis band: shed a stream when load is above gpu_high (85%), admit one when below gpu_low (60%), hold steady in between, clamped to [min_slots, max_slots].
So prioritisation only bites when the hardware is actually saturated (or when more cameras have motion than the hard ceiling). With headroom, every moving camera is scanned and nobody is deprioritised. When it does bite, slots go to the highest-priority cameras, ties broken deterministically so slots don't flicker. The header stat bar shows live GPU%, CPU%, slots (active/effective/cap) and a ⚠ Contention pill; each camera shows online/fps/SCANNING-WAITING-idle and a ● REC marker. The full algorithm — including recommended priority bands and how to force a visible demo (max_batch_size: 2) — is in docs/PRIORITY_AND_LOAD.md.
